# 04. 収益とマーケティング

最終更新: 2026-06-03

## 1. 収益設計（アフィリエイト）

### 全体の考え方

> サイト（網羅＋ピック）→ SNS/note で認知 → クリック → 成果計測 → 何が売れたかを選書にフィードバック → 先頭に戻る

### 収益経路と着手順

| 経路 | いつ | ポイント |
|---|---|---|
| **① 楽天アフィリエイト** | **初日から** | 楽天APIの `affiliateUrl` をそのまま使う。登録すれば即収益化。**収益の起点** |
| **② もしもアフィリエイト経由のAmazon** | Phase 2 | 「かんたんリンク」でAmazon＋楽天＋Yahooを1ボックス表示。Amazon提携の審査ハードルが低く、W報酬（ボーナス報酬）あり。**Amazon直の「3件の壁」を回避できる現実的ルート** |
| **③ Amazon直アソシエイト** | Phase 3（本命）| 後述の「180日で3件」をクリア → 本審査 → 正式利用。料率や自由度で本命だが、コンテンツが育ってから |
| **④ PA-API（価格・在庫の自動取得）** | Phase 4 | 売上実績が前提。リンクを貼るだけなら不要なので最後 |

### Amazon直アソシエイトの審査（裏取り済み・重要）

- リンク経由で **入会後180日以内に3件の適格販売** が発生すると本審査が行われ、通過すると正式利用可能。
- **自己購入・家族や友人への依頼購入はカウントされない**（規約違反）。
- 適格販売は「クリックから24時間以内にカート追加 → 89日以内に購入」が条件。
- 本審査では **10記事以上の充実したコンテンツ・オリジナル文** などが見られる傾向。
  - → だから **サイトとnoteに記事がそろってから申請する**のが定石。新刊紹介の導線で3件を取りに行く。
- 出典:
  - [Amazonアソシエイト審査条件 2026（キラッとはてログ）](https://poyaran.com/entry/amazon-associate-requirements)
  - [「3件の壁」突破法](https://poyaran.com/entry/amazon-associate-screening)
  - [もしもアフィリエイト経由でAmazon提携](https://terihat.com/amazon-via-moshimo/)

### 規約上の注意（収益まわり）

- **書影のSNS利用**は販促・紹介目的の範囲かを確認。
- **あらすじ等の転載は不可** → 要約・オリジナル文に。
- **Amazon/楽天アフィリンクのチャネル制限**: メールや一部SNSでのリンク利用に制限あり。配信前に各規約を確認。

## 2. 集客（SEO）— サイト本体に内蔵する最重要要素

本のサイトで一番購入につながる流入は、たいてい **「書名＋発売日／あらすじ」のロングテール検索**。

### ① プログラマティックSEO（データが増えるほどページが増える構造）

- `books` テーブルの各行 → **書籍詳細ページ**に自動展開。
- さらに自動生成: **著者ページ / 出版社ページ / ジャンルページ / 「○年○月の文芸新刊」ページ**。
- これらを内部リンクで結ぶ。データが増えるほど入口が増える。

### ② 構造化データ・インデックス促進

- 各ページに **Book / ItemList schema**（検索エンジンに「これは本です」と伝える印）を埋める。
- **自動サイトマップ** ＋ **IndexNow / Search Console API** で新着を素早くインデックス。

## 3. SNS/note — 「半自動パブリッシング」（生成は自動・投稿は安全に）

### 発想の転換（凍結対策）

アカウント凍結の主因は、自動フォロー/いいねの連打・同一文の連投などプラットフォーム規約外の挙動。
公式APIを規約内で使う分には凍結リスクは低い。
そこで **「投稿そのものを自動化する」のではなく「生成は自動・投稿は安全な経路＋人の確認」** に切り替える。

```
Supabase（新刊・注目作）
  → 下書き生成エージェント（LLMが投稿文を毎回ユニークに作成）
  → 承認キュー（ダッシュボード / LINE / Discord に通知）
  → ① 公式APIで投稿  または  ② FJさんが1タップで手動投稿
```

この **承認ゲートは、BAN対策であり、同時に「AIっぽさ」を弾く品質チェック**にもなる。

### 運用ルール（凍結されにくくする）

- 毎回 文面をLLMで変えて、同一文の連投を避ける。
- 投稿間隔をあけ、1日の本数を抑える。
- URLだけ／ハッシュタグ過多の投稿を避ける。
- **自動フォロー・自動いいねは絶対にやらない**（最も凍結されやすい）。
- アフィリンクのチャネル制限（メール等）を配信前に確認。

### note/まとめ記事

- 指名検索・ファン化の起点。
- 同時に **Amazon直アソシエイトの本審査用コンテンツ**としても効く（記事数が評価される）。

## 4. 計測（KPIダッシュボード）— 後フェーズ

- 楽天アフィリエイト／もしも／A8.net のレポート、GA4、Search Console を束ねて
  「どのSNS・記事・ページが成果になったか」を可視化。
- その結果を **注目作・テーマの選定にフィードバック**（先頭の循環に戻す）。
- 既存の「Tavily ＋ Next.js ニュースダッシュボード」の作りを転用できる見込み。

## 5. まとめ：効く順

1. **プログラマティックSEO（サイト本体に内蔵）** — 最重要。購入に直結する流入源。
2. **楽天アフィリエイト** — 初日から収益化。
3. **note/まとめ記事** — ファン化＋Amazon審査用コンテンツ。
4. **半自動パブリッシング（承認キュー付き）** — 認知拡大を安全に。
5. **もしも経由Amazon → Amazon直** — 段階的に。
6. **KPIダッシュボード** — 成果を選書に還元。
