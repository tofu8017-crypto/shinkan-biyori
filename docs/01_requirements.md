# 01. 要件定義（REQUIREMENTS）

最終更新: 2026-06-03 / ステータス: Phase 0（要件定義中）

凡例: ✅ 決定済み ／ 🔲 未決（推奨案つき。詳細は [05_open_questions.md](05_open_questions.md)）

---

## 1. プロダクトの目的

各出版社を横断して「今日（および前後の期間）に発売される文芸書」を毎日自動でまとめ、
Amazon・楽天などの購入リンク（アフィリエイト対応）とともに、カレンダー形式で見せるサイト。
**「本を見つけるのにいい日」**という温かさを軸に、毎日更新でファンがつく媒体を目指す。

## 2. サイトの性格 ✅

**網羅ベース ＋ 注目作のピックアップ** の両立。

- **網羅**: 対象期間の文芸新刊を全部カレンダーに載せる（検索・絞り込みで探せる）。
- **ピック**: その中から編集視点で「注目作」を選んで前面に出す（ファン化・指名検索の起点）。

## 3. 対象範囲（「文芸書」の定義）✅（広め）

小説を中心に、**エッセイ・ノンフィクションなど広めに取る**。
→ 楽天ブックスのどのジャンルIDを「文芸」とみなすかは 🔲 未決（[05](05_open_questions.md) Q6）。
実務上は「文学・評論」「エッセー」「ノンフィクション」系ジャンルを束ねる想定。

## 4. 機能スコープ

### 4.1 必須機能（MVP）

- **新刊カレンダー** 🔲 — 月表示で日ごとに新刊点数のバッジ→日付クリックで当日一覧（推奨案）。
- **新刊一覧** ✅ — 発売日順。タイトル・著者・出版社・書影・価格・ジャンルを表示。
- **書籍詳細ページ** ✅ — 1冊ごとに独立ページ（書影・内容紹介・購入リンク）。SEOの核（→ [04](04_monetization_marketing.md)）。
- **購入リンク** ✅ — 楽天（アフィリエイト）＋Amazon。最初はISBNベースのリンク。
- **検索・絞り込み** ✅ — タイトル・著者・出版社・ジャンル・在庫状態で絞れる。
- **注目作ピック** ✅ — トップや一覧上部で目立たせる。選定方法は 🔲（[05](05_open_questions.md) Q7）。

### 4.2 発売日ウィンドウ（カレンダーに載せる期間）🔲

推奨: **過去7日＋当日＋今後30日（近刊）**。前後に見られて、近刊予約の導線にもなる。

### 4.3 その他の購入先 🔲

推奨: まずは **Amazon＋楽天の2つ**に絞る。将来 楽天Kobo・honto を追加検討。

### 4.4 後フェーズの機能（拡張）

- プログラマティックSEO（著者・出版社・ジャンル・月別ページの自動生成）→ [04](04_monetization_marketing.md)
- 構造化データ（Book / ItemList schema）・自動サイトマップ・IndexNow
- 半自動パブリッシング（SNS/note 下書き自動生成＋承認キュー）→ [04](04_monetization_marketing.md)
- KPIダッシュボード（楽天/A8/GA4/Search Console を束ねる）
- PA-API による価格・在庫の自動取得（売上実績が前提なので最後）

## 5. 非機能要件

- **規約順守を最優先**（凍結・アカBAN回避）。楽天APIは1秒1リクエスト、openBDのキャッシュは変更を早く反映、書影は「本の紹介目的」の範囲、あらすじは**転載せず要約＋出典明記**。詳細→ [02](02_data_and_api.md)。
- **データ取得は公式APIのみ**（スクレイピングしない）。理由: 規約・安定性・凍結リスク回避。
- **SEO重視**: 各書籍が検索流入の入口になる設計（ロングテール検索＝「書名＋発売日／あらすじ」を狙う）。
- **無料枠で回す**: Supabase 無料枠・Vercel 無料枠・GitHub Actions 無料枠の範囲で運用開始。
- **保守が軽い**: 1人で維持できること（競合の実例が証明済み）。

## 6. 決定済み事項まとめ ✅

| 項目 | 決定 |
|---|---|
| ブランド名 | 新刊日和 |
| サイトの性格 | 網羅 ＋ 注目作ピック |
| 文芸書の範囲 | 広め（小説＋エッセイ＋ノンフィクション等）|
| 主データソース | 楽天ブックスAPI（取得・アフィリエイト）＋ openBD（書誌・書影補完）|
| 正規化キー | ISBN（ISBN-13を主キー、ISBN-10も保持）|
| 技術スタック | Next.js + Supabase + Vercel + 日次バッチ |
| データ取得方式 | 公式API（スクレイピング禁止）|
| 収益の起点 | 楽天アフィリエイト（登録初日から収益化可能）|

## 8. フェーズ計画（MVP→拡張）

- **Phase 0（今ここ）**: 要件確定。
- **Phase 1（MVP）**: 楽天API取得→openBD補完→Supabase保存→Next.jsで一覧・詳細・カレンダー・楽天アフィリンク。GitHub Actions（または Vercel Cron）で日次。Vercel公開。
- **Phase 2**: もしもアフィリエイト経由でAmazonリンク追加、注目作ピック、プログラマティックSEO（著者/出版社/月別）、構造化データ、サイトマップ。
- **Phase 3**: 半自動パブリッシング（承認キュー）、note連携、KPIダッシュボード、Amazon直アソシエイト申請。
- **Phase 4**: PA-API（価格・在庫の自動取得）、近刊予約導線の強化。
