# はてなブログ自動投稿ツールキット

はてなブログに「読んで役に立つ独自記事」を投稿し、本文中から自分のサイトへ
**dofollow リンク**を自然に張って、サイトの評価(ドメインパワー)を底上げするためのツールキットです。

> ⚠️ 被リンクは「良い記事 × 自然なリンク密度」で初めて効きます。
> リンクを張るためだけの薄い記事は、検索エンジンにスパムと見なされ逆効果です。記事の質を最優先に。

## あなた (呼び出し側) が決めておくこと

このスキルは「**どう書いて、どう投稿するか**」の手順書です。
次の3つは、使う人 (またはエージェント) 側で決めてください。

1. **何について書くか** — 記事のテーマ (あなたのサイトの読者が検索しそうなネタ)
2. **誰の口調で書くか** — 書き手の人格 (一人称・語り口)。例:「編集部の〇〇」として親しみやすく
3. **どこにリンクするか** — あなたのサイトの URL。リンク先が実在する(404でない)ことを必ず確認

## 必要な環境変数 (.env)

| キー | 用途 |
|---|---|
| `HATENA_ID` | はてな ID |
| `HATENA_BLOG_HOST` | ブログのドメイン (例: yourname.hatenablog.com) |
| `HATENA_API_KEY` | AtomPub API キー (はてなブログ 詳細設定 → API キー) |
| `GEMINI_API_KEY` | 画像生成 (https://aistudio.google.com/) |

## 全工程

```
[Step 0] 起動チェック  … 今日もう投稿していないか (check-daily-limit.sh)
   ↓
[Step 1] テーマ決定    … 過去記事と被らないか (check-dup.sh)
   ↓
[Step 2] ファクトチェック … 記事の事実を一次情報で確認
   ↓
[Step 3] 執筆          … あなたの人格で 2,000〜3,000 字。自サイトへ dofollow 2〜3 本
   ↓
[Step 3.5] 画像        … アイキャッチ + 図解を生成 → フォトライフへ → 本文に埋め込み
   ↓
[Step 4] セルフレビュー … AI臭チェック (lint-anti-ai.sh) + チェックリスト
   ↓
[Step 5] 投稿          … post-hatena.sh で公開 → record-post.sh で記録
```

## Step 0: 起動チェック

```bash
bash .claude/skills/hatena-auto-poster/scripts/check-daily-limit.sh 1 || { echo "本日は投稿済み。終了。"; exit 0; }
```

1日に何本も投稿するとスパム判定の恐れがあります。既定では1日1本まで。

## Step 1: テーマ決定

あなたのサイトの読者が検索しそうなテーマを1つ選びます。
過去に書いたテーマと被らないことを確認します(被ると検索評価が分散します)。

```bash
# 識別語 (地名・固有名詞・制度名など) を中心に渡す
bash .claude/skills/hatena-auto-poster/scripts/check-dup.sh "東京 子育て 給付金"
# exit 1 が出たら別の切り口にする
```

## Step 2: ファクトチェック

記事で触れる数字・事実は、公式サイトなど一次情報で必ず確認します。
確認できないことは断定せず「詳しくは公式サイトをご確認ください」と逃がします。
(古い情報や誤りを公開すると、サイト全体の信頼を損ないます。)

## Step 3: 執筆

- あなたが決めた**書き手の人格**で、冒頭に自己紹介・末尾に署名を入れる
- **2,000〜3,000 字**。具体的な情報を入れて読み応えを出す
- 自サイトへの **dofollow リンクを 2〜3 本**、文章に自然に溶け込ませる
  - アンカーテキスト(リンクの文字)は「〇〇の詳細」など**具体的な言葉**に。「こちら」の連発は避ける
  - リンク先 URL は**実在を必ず確認**(ブラウザや `curl` で 200 が返るか)
- 末尾に「関連記事」リストを置くと、追加のリンクを自然に作れます

本文は Markdown でファイルに書き出します:
```bash
BODY="$(mktemp)".md
cat > "$BODY" <<'EOF'
(ここに本文)
EOF
```

## Step 3.5: 画像 (アイキャッチ + 図解)

画像があると記事一覧や SNS シェアの見栄えが上がり、「手間をかけた記事」に見えます。
画像は**はてなフォトライフ**(はてな公式の画像置き場)に直接アップするので、外部サービスは不要です。

```bash
# 1) アイキャッチを生成 (記事内容に合うものを。Gemini が jpg を返すこともあるので実パスは $IMG を使う)
IMG=$(bash .claude/skills/hatena-auto-poster/scripts/gen-image-gemini.sh "横長16:9のブログアイキャッチ。テーマ『(記事テーマ)』。明るいフラットイラスト。広告っぽくしない。" /tmp/eyecatch.png)

# 2) フォトライフへアップロード
RESULT=$(bash .claude/skills/hatena-auto-poster/scripts/upload-fotolife.sh "$IMG" "(記事タイトル)")
SYNTAX=$(printf '%s' "$RESULT" | cut -f1)   # [f:id:...:image]  ← 本文に貼る
```

生成した画像は**必ず目で確認**(意図と違う絵・文字化けがないか)。
`$SYNTAX` を本文の好きな位置に1行で貼ると画像が表示されます(冒頭=アイキャッチ、本文途中=図解)。
図解(金額の比較表など)を足したいときも、同じ手順でもう1枚作って該当箇所に貼るだけです。

## Step 4: セルフレビュー

公開前に、書き手とは別の目線で読み直します。

```bash
bash .claude/skills/hatena-auto-poster/scripts/lint-anti-ai.sh "$BODY"   # AI っぽい定型表現が無いかチェック。exit 1 なら直す
```

そのうえで次を全部 ✅ にしてから公開:

1. 検索需要のあるテーマか
2. 自サイトへの dofollow リンクが 2〜3 本か(多すぎない)
3. リンク先 URL が実在するか(404 でない)
4. アンカーテキストが具体的か
5. 事実確認が済んでいるか
6. 書き手の人格で自己紹介+署名があるか
7. AI 臭フレーズが無いか(lint 通過)
8. 過去記事と被っていないか
9. 2,000〜3,000 字あるか
10. アイキャッチを1枚以上入れたか(目視確認済み)

## Step 5: 投稿

```bash
URL=$(bash .claude/skills/hatena-auto-poster/scripts/post-hatena.sh \
  --title "記事タイトル" \
  --body-file "$BODY" \
  --category "カテゴリ1" --category "カテゴリ2" \
  --draft no)            # ← まず試すときは --draft yes で下書きにできる
echo "公開: $URL"

# 投稿を記録 (本数制限・重複チェックが参照する)
bash .claude/skills/hatena-auto-poster/scripts/record-post.sh "記事タイトル" "東京 子育て 給付金" "$URL"
```

## ハードルール (まとめ)

- 1日1本まで(スパム防止)
- dofollow リンクは 2〜3 本(詰め込まない)
- リンク先は実在確認必須(404 を作らない)
- 独自コンテンツ(他記事のコピペ・焼き直し禁止)
- 読者価値優先(リンク目的だけの薄い記事は逆効果)
- 公開前に必ずセルフレビュー(lint + チェックリスト)
- 事実は一次情報優先(不明なことは断定せず逃がす)
